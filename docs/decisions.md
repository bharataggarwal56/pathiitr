# Decisions

One line per significant decision, newest last.

- 2026-10-27: Stack is Next.js (App Router, TS) + Tailwind on Vercel, Supabase for Postgres/pgvector/Auth; Rs 0 budget, free tiers only.
- 2026-10-27: LLM calls go through one `lib/llm.ts` wrapper: Groq primary, Gemini free tier as automatic fallback on rate limits.
- 2026-10-27: Embeddings are computed locally, not via a paid API.
- 2026-10-27: Login is Google via Supabase Auth, restricted to iitr.ac.in accounts.
- 2026-10-27: Repo is public and code-only; all source material lives in gitignored `data/` and is anonymised before reaching Supabase.
- 2026-10-27: Pre-commit hook is tracked in `scripts/hooks/` and enabled via `git config core.hooksPath` (`scripts/setup-hooks.sh`); blocks `data/`, `.env*`, files over 1 MB, API keys, full IITR emails and phone numbers. No bypass.
- 2026-10-27: Python scripts use pymupdf (PDF text + page rendering for OCR), python-docx, python-pptx, pytesseract, groq and google-genai (not the deprecated google-generativeai); Markdown is read as plain text; direct deps pinned in `scripts/requirements.txt`.
- 2026-10-27: Inventory merges exact (SHA-256) and near (>90% text similarity) duplicates into one row listing all tracks; every document has a `display_title` with no personal names, and the app/later steps show that, never the original file name.
- 2026-10-27: `scripts/extract.py` writes one Markdown file per document to `data/work/text/`, named `<display_title slug>-<sha8>.md`; PDF pages with under 25 selectable characters are OCR'd (Tesseract, 300 dpi), capped at the first 15 such pages for `kind=reference` files (summary/topics only); links are kept; .doc/.ppt are converted only if LibreOffice is installed (optional).
- 2026-10-27: The `path` field in extracted text headers holds original file names (some contain people's names); it stays in `data/work/` for tracing only, is never loaded into Supabase or shown in the app, and later steps use `display_title` only.
- 2026-10-27: `scripts/anonymise.py` writes `data/work/clean/`; regex removes emails, phones, roll numbers and personal profile links in all files; names (spaCy `en_core_web_sm` + signature-line and Prof./Dr. rules) are replaced only in `kind=guidance` files, case-sensitively, with "a senior" ("a professor" for Prof./Dr.); one-word or mixed names containing ordinary English words are only flagged in the report; `path:` is dropped from clean headers.
- 2026-10-27: Learning-resource links come from `scripts/harvest_links.py` (all URLs in `data/work/clean/` + structured JSON, minus resume links and non-URLs); `data/work/skill_matrix.json` is hand-drafted and may only use URLs from that list, checked by `scripts/check_skill_matrix.py`. Skills with no link in our docs stay as listed gaps; Drive copies of published textbooks are left out.
- 2026-10-27: `scripts/extract_courses.py` builds `data/work/courses.json` from the curriculum structure PDF; `topics` stays null until syllabus PDFs are added; elective→track mapping is hand-kept in `data/work/elective_tracks.json`, based on course titles only. ECE Core stays one track with sub_area tags rather than separate sub-tracks.
- 2026-10-28: `scripts/embed.py` writes `data/work/chunks.jsonl` with gte-small (384 dims; ONNX weights from `Supabase/gte-small` at a pinned revision, mean pool + L2 normalise), the same model Supabase Edge Functions run built in (`Supabase.ai.Session('gte-small')`) for embedding questions; guidance docs are chunked in full (~300 tokens, ~50-token sentence overlap, heading starts a chunk, page tracked, Notion front matter dropped); the curriculum is chunked from `courses.json` (one chunk per semester, one per elective group with mapped tracks, labelled as title-based), not the PDF text; each reference doc gets one chunk from its structured summary + topics only; inputs must fit 512 tokens incl. [CLS]/[SEP].
- 2026-10-28: Pre-commit phone check ignores 10-digit runs glued to letters (e.g. inside hex hashes such as the pinned model revision); phones separated by spaces/punctuation are still blocked.
- 2026-10-28: Web app scaffolded with create-next-app (Next 16.4, React 19, Tailwind v4, cacheComponents on, `agentRules: false` since CLAUDE.md holds the rules); Supabase via `@supabase/ssr` helpers in `lib/supabase/` (browser, server, proxy) with root `proxy.ts` refreshing the session via `getClaims()`; palette in `app/globals.css` `@theme`: navy #0b1f3a, blue #1f4e9c, tint #e8eef8, white surfaces, amber accent #e8a33d; IITR logo is the header mark and favicon.
- 2026-10-28: Login allows any `@iitr.ac.in` email incl. department subdomains (`@ece.iitr.ac.in` etc.), regex in `lib/auth.ts`; the gate runs in `/auth/callback` (non-IITR → sign out + `/?auth_error=domain`) and again in the proxy, which also redirects signed-out users on every path except `/` and `/auth/*`; the header sign-in/out control is a client component so layouts stay prerenderable under cacheComponents. A pre-signup Supabase hook and RLS checks are deferred to the data features.
- 2026-10-29: Landing-page stats (tracks, experiences, ECE courses, source documents) come from `lib/site-stats.json`, written by `scripts/site_stats.py` from `data/work/` and committed with counts only (Vercel cannot see `data/`); the experiences stat is labelled "experiences from seniors and CDC" (75 entries, 0 cross-document duplicates, 2 same-key repeats within one doc; `experiences_unique` also stored); footer shows the stats date. Icons via `lucide-react`. Pages set their own width with the `page-container` utility so the home hero runs full width; the header is sticky.
- 2026-10-29: Schema in `supabase/migrations/20261029120000_initial_schema.sql` (run via SQL Editor): content tables (`tracks` incl. non-career `Cross-track`, `documents` with no file path, `chunks` vector(384) HNSW cosine, `experiences`, `skill_matrix` with resources as jsonb, `courses` merged with elective mapping, `curriculum_slots`) are select-only for authenticated users passing `is_iitr_user()` (SQL mirror of `isAllowedSession`) and written only by loaders with the secret key; `profiles`, `conversations`, `chat_messages` (no update) and `message_feedback` (assistant messages only) are own-rows-only, with composite FKs tying children to the same user; `llm_cache` is server-only (RLS, no policies) and holds non-personalised answers only; no resume table. `match_chunks` caps results at 8 and adds +0.03 to guidance/curriculum scores (`prefer_guidance`, default on) so reference summaries don't crowd out seniors' advice. Users can insert "assistant" rows into their own history; accepted, since it only affects them. Grants are explicit, and anon gets nothing.
- 2026-10-29: `scripts/load.py` upserts `data/work/` into the six content tables over the Supabase REST API with the secret key (`requests`, no new SDK): idempotent on natural keys, prunes stale rows only from a hard-coded content-table allowlist (`--no-prune`, `--dry-run`), runs the anonymise regexes over everything before writing, stops on "permission denied" instead of working around grants; `documents` holds metadata only (text lives in `chunks`), the curriculum doc takes its metadata from the clean/ front matter, and slot credits "3/4" are stored as 3 (smallint column).
- 2026-10-29: `lib/llm.ts` calls Groq (`openai/gpt-oss-120b`, reasoning low) and Gemini (`gemini-3.5-flash`) over REST with `fetch`, no SDKs, 15 s timeout each; Groq 429/413/5xx/timeout/network errors fall back to Gemini, both failing gives `LLMBusyError` ("busy, try again shortly"), other 4xx are thrown as real errors. Optional cache in `llm_cache` via a secret-key admin client (`lib/supabase/admin.ts`): key = sha256 of JSON `[promptVersion, scope, normalised question]`, where the caller's `scope` carries the track filter + data version; questions matching the anonymise regexes (`lib/pii.ts`, a port of `scripts/anonymise.py` minus names) skip the cache entirely; cache errors never fail a request. `server-only` is imported by `lib/llm.ts` and `lib/supabase/admin.ts` so client imports break the build. `/api/llm-test` is dev-only (404 in production); `LLM_DEBUG_FAIL=groq|both` simulates rate limits in dev only.
- 2026-10-29: Chat questions are embedded by the Supabase Edge Function `embed` (`supabase/functions/embed/`, built-in `Supabase.ai` gte-small, mean pool + normalise; same top-5 ids and similarities as `embed.py --search`), deployed with `npx supabase@2 functions deploy --use-api`; it verifies the caller's token with `getClaims` and applies the `isAllowedSession` rule itself (403 for non-IITR), and sends no CORS headers since only the Next server calls it.
- 2026-10-29: `/api/chat` streams NDJSON (`sources`, `delta`…, `done` | `error`), no AI SDK; `lib/llm.ts` `generateStream` parses Groq/Gemini SSE by hand, falls back to Gemini only before the first token, marks mid-stream failures as cut off (not cached), and retries a failed connection once (this network drops some connections to Cloudflare hosts).
- 2026-10-29: Retrieval: top 5 chunks via `match_chunks` as the logged-in user (RLS); a picked track searches track + `Cross-track` + `curriculum`; below 0.80 similarity (on-topic 0.83-0.91, off-topic 0.74-0.79) the answer is "not covered" without an LLM call. Each chunk is passage [k] in the prompt; `citeDocuments` maps passages to one number per document and drops invalid numbers, so the sources list is one row per document. Cache scope = track + hash of retrieved chunk ids; prompt version `chat-v3`.
- 2026-10-29: Questions that look Hindi/Hinglish (Devanagari or common words like kaise/kya/ke liye/hai) are rewritten to an English search query with an uncached `generate()` call before embedding; English questions skip it. Answers are always in English.
- 2026-10-29: Per-user limit of 15 questions per 10 minutes, counted from the user's own `chat_messages` before any embed/LLM call (a user deleting their messages could reset it; acceptable). Each question is retrieved on its own; follow-ups don't carry earlier turns.
- 2026-10-29: Answers render with `react-markdown` (no raw HTML); citation markers become chips linked to the sources list. Thumbs up/down upsert `message_feedback` from the browser client under RLS; clicking the chosen thumb again removes it.
- 2026-10-29: Vercel functions run in `bom1` (Mumbai, `vercel.json`) next to Supabase (ap-south-1); the default `iad1` put every Supabase round trip across the world (2-3 s before the LLM even started).
- 2026-10-29: The app's Gemini fallback is `gemini-3.6-flash` with `thinkingLevel: "minimal"` and a 25 s first-reply timeout (Groq keeps 15 s); free-tier tests gave first tokens in 6-10 s vs 25 s+ (or 503) for `gemini-3.5-flash`, which the batch scripts keep. Groq's gpt-oss-120b free tier allows about 8k tokens/min (~3-4 chat answers/min across all users), so the fallback matters in a busy demo.
- 2026-10-29: LLM fallback chain is Groq `openai/gpt-oss-120b` (reasoning low) → Groq `qwen/qwen3.8-27b` (reasoning none) → Gemini `gemini-3.6-flash` (supersedes "Groq primary, Gemini fallback"). Each Groq model has its own free bucket (8k tokens/min, 1k requests/day each, read from Groq's rate-limit headers on 2026-10-29), so the backup absorbs bursts at Groq speed and Gemini (6-25 s first token) is the last resort. qwen3.8-27b over the preferred gpt-oss-20b because in local tests 20b left every bullet uncited in 2 of 6 answers (low and medium reasoning; medium also burned its quota), qwen cited all 4 of 4 at 1.5-4 s (small sample; it said "not covered" once where others answered). Streaming moves to the next step only before the first token. `LLM_DEBUG_FAIL` takes a comma list of step ids (`groq`, `groq-backup`, `gemini`) or `all`.
- 2026-10-29: Chat prompt `chat-v9` (same for every provider): every bullet carries its own [n] (no citations grouped at the end; the rule is repeated with an example right before the question, because smaller models ignored it when it was only in the system prompt), and answers never say "The provided sources", "The sources", "the context", "the passages" or "the documents"; what isn't covered is said in plain words ("No CGPA cut-off is listed for …").
- 2026-10-29: Grounding: the prompt requires every claim to come from one passage (no company from one passage paired with a number from another). After each answer, `unmatchedFigures` (plain text check, no LLM call) looks for every number on each line among the numbers in the passages that line cites; any miss, or a number on an uncited line, appends "Some figures above couldn't be matched to the sources. Please check the cited documents." The check also runs on cached answers.
- 2026-10-29: Answers are cleaned deterministically wherever they are shown or saved (`neutralizePhrases` in `lib/chat-shared.ts`): clauses like "from the sources" / "according to the context," are dropped and other mentions of "the (provided) sources/material/context/passages/documents" become "PathIITR's data" ("in the context of …" is left alone). Any line with a CGPA, stipend, eligibility, cut-off, CTC or LPA figure adds a quiet note: "Eligibility figures vary by company, role and year. Open the cited source to confirm." Prompt version `chat-v10`.
- 2026-10-29: Onboarding (`/onboarding`) stores year, branch code, interest ids, target tracks (max 3) and `profiles.skill_levels` = `{area id: 0-3}` (none/beginner/intermediate/strong) over 22 hand-kept skill areas in `lib/careers/skills.ts`, each listing the exact `skill_matrix` names it covers (every matrix skill in exactly one area; `loadMatrix` logs any gap against the live table in dev, `npm test` checks the helper). Students rate areas, not the ~67 matrix skills; area and interest ids are stored, so they are only ever added, never renamed. The skill-gap page reuses `trackSkillStatus` on the same profile, no second form. Migration `20261029180000_profile_onboarding.sql` drops the unused `profiles.skills`, adds `skill_levels` (jsonpath checks), `recommendation`, `onboarded_at`.
- 2026-10-29: Career recommender is rules only (`lib/careers/recommend.ts`): score = 60 × weighted skill fit (core 2, nice-to-have 1, level/3) + 12.5 per matching interest (max 2) + 15 if picked as a target; ties by skill fit then track order; reasons and "next to learn" gaps are templates. No branch rule, so non-ECE students still see ECE Core. The result is stored in `profiles.recommendation` with a hash of its inputs (profile + matrix + rules version) and recomputed on each careers view, rewritten only when the hash changes.
- 2026-10-29: The LLM only rewrites the top-3 reasons into a short friendly summary (`/api/careers/explain`, `generate()`, no `llm_cache` since it is personalised): the prompt holds track names, reason strings and the year as a word, no branch or scores; the text is stored in the profile's recommendation, so it is one call per profile change, not per view; text containing any digit (other than "2nd year"-style ordinals) is dropped and stored as empty. Busy errors show the friendly message with a retry while the rule-based cards stay visible. `npm test` runs `node --test` on `lib/careers/*.test.ts` (Node type stripping, hence `allowImportingTsExtensions` and `.ts` imports inside `lib/careers/` pure modules).
- 2026-10-29: Skill-gap page (`/skill-gap?track=`, default the top recommended track, bad values fall back to it) reads `profiles.skill_levels` through `trackSkillStatus`, no second form: Have = intermediate/strong, Partly = beginner, Missing = none; resources come only from `skill_matrix.resources` (drive links tagged "seniors' drive"), otherwise "No resource in our documents yet". The LLM's "what to learn first" text (`/api/skill-gap/priorities`, `generate()`, no `llm_cache`) gets only the track, year as a word and the non-Have skills with core/nice-to-have and partly/missing; it must use "-" bullets (shown as a numbered list) so any digit or link drops it, stored as "". Stored per track in `profiles.skill_gap` = `{track: {version, inputHash, text}}` (migration `20261029200000_skill_gap_priorities.sql`); the hash covers only that track's skills and ratings plus the year, so unrelated edits keep it. `hasFigures` moved to `lib/careers/figures.ts`. "Next to learn" items on `/careers` link to `/skill-gap?track=…#<skillAnchor>`. Data components on `/careers`, `/onboarding` and `/skill-gap` call `await connection()` first: with Partial Prefetching on, Next pre-renders them for prefetch and flagged the Supabase client's `Date.now()`.
- 2026-10-30: Electives page (`/electives?track=`) reads `courses` (category elective) with no LLM and no migration; groups are program electives (`pec`), TEB-A..H baskets (`teb` + `elective_group`) and open electives (`oec`), and a course on several lists shows in each group (minor/honours-only courses are left out). Default filter is the top recommended track, or All when the profile isn't onboarded; `?track=all` is the explicit All. Courses that help the chosen track are highlighted and listed first. A permanent note says suggestions come from course titles (syllabi weren't available). Grouping lives in `lib/careers/electives.ts` (tested).
- 2026-10-30: Public `/privacy` page (in the proxy's public paths, linked in the footer) states what is stored, what never is, IITR-only sign-in and the Groq/Gemini processing. The support email is read from `NEXT_PUBLIC_SUPPORT_EMAIL` (env, not in the public repo); unset falls back to a GitHub-issue line.
- 2026-10-30: Roadmap page (`/roadmap?track=`, default the top recommended track) is rules only, no LLM and no migration (`lib/careers/roadmap.ts`, tested): the current semester comes from `profiles.study_year` and the date (Jul-Dec Autumn, Jan-Jun Spring), and the plan runs to Year 4 Spring. Core courses and `curriculum_slots` go in their semester; `ECL-*` slots suggest up to 3 PEC and `ECT-*` up to 3 TEB courses that help the track by title (matching `offered` when set), each course suggested once in the plan. OEC/HSSEC/MSC-DHC/ECP slots get a fixed note, no suggestions (our data has only ECE's own OECs and no HSS courses). Non-"have" skills from `trackSkillStatus` are spread 2-3 per semester, missing core first. Non-ECE branches see only the skill plan. "Print / save as PDF" uses `window.print()` with Tailwind `print:` variants (header, footer and track nav hidden).
